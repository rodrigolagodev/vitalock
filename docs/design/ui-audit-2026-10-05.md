# UI Design Audit — Apple HIG lens (2026-10-05)

Scope: `apps/admin` (desktop SPA), `apps/installer` (mobile PWA), `packages/ui`.
Method: static code audit (no live screenshots), scored with the 6-dimension rubric, Nielsen's 10 heuristics, WCAG 2.2 AA, and Apple's design principles as the reference lens. Apple's principles here are clarity, deference, depth through surfaces, one accent, a strict type ladder, radius tiers, 44pt targets and motion that respects reduced-motion.
Contrast ratios were computed from the HSL tokens in `packages/ui/globals.css`.

## 1. Scores

| Dimension        | Weight | Score        | Why                                                                                                                                                                   |
| ---------------- | ------ | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Visual hierarchy | 20%    | 5            | Section heading (28px) is larger than page h1 (24px). Four different section-heading conventions. Secondary text is washed out (2.2:1).                               |
| Consistency      | 20%    | 5            | Button 52px next to input 44px. Radius drift (md/lg/xl on containers). Spinner vs skeleton. ConfirmDialog vs hand-rolled dialogs vs `window.confirm`.                 |
| Accessibility    | 20%    | 4            | `muted-foreground` 2.19:1 (183 uses). Input border 1.47:1. Dark semantic pairs 1.5–1.9:1. Errors not linked to inputs. No reduced-motion handling. 28px icon buttons. |
| Usability        | 20%    | 6            | Good inline validation and toasts. Empty and error states lack icon and retry. Installer primary actions sit at the top of long pages.                                |
| Responsiveness   | 10%    | 5            | Installer reuses the desktop shell (hamburger FAB). No safe-area insets. iOS focus-zoom on textarea.                                                                  |
| Performance      | 10%    | 6            | Skeletons on most lists. No offline data cache. Some raw spinners.                                                                                                    |
| **Overall**      |        | **5.1 / 10** | Adequate. The foundation (tokens + `@vitalock/ui`) is solid; the debt is in calibration and consistency, not architecture.                                            |

Strengths to keep: every icon-only control requires a label (`IconButton.label`). StatusBadge never relies on color alone. All mutations get toasts. No raw hex in source. Dark mode has no flash (`theme-init.js`).

## 3. Target system (Apple-inspired, mapped to existing tokens)

Do not copy Apple's palette or brand. Adopt its grammar: neutral surfaces, one action color, a strict type ladder, radius tiers and quiet chrome.

**Typography**: explicit system stack in the preset. Today no font is declared; the stack only resolves through Tailwind defaults.

```js
fontFamily: {
  sans: [
    '-apple-system',
    'BlinkMacSystemFont',
    '"SF Pro Text"',
    'Inter',
    '"Segoe UI"',
    'Roboto',
    'sans-serif',
  ];
}
```

| Token              | Admin (desktop) | Installer (touch) | Weight | Use                            |
| ------------------ | --------------- | ----------------- | ------ | ------------------------------ |
| `text-large-title` | —               | 34/41             | 700    | Installer screen title         |
| `text-title-1`     | 28/34           | 28/34             | 600    | Page h1                        |
| `text-title-2`     | 22/28           | 22/28             | 600    | Detail hero / dialog title     |
| `text-title-3`     | 18/24           | 20/25             | 600    | Section heading                |
| `text-headline`    | 15/20           | 17/22             | 600    | Card titles, emphasized values |
| `text-body`        | 14/20           | 17/22             | 400    | Default text                   |
| `text-callout`     | 13/18           | 16/21             | 400    | Secondary text                 |
| `text-footnote`    | 12/16           | 13/18             | 400    | Field errors, timestamps       |
| `text-caption`     | 11/13           | 12/16             | 500    | Table headers, eyebrows        |

Use `tabular-nums` on prices, totals and quantities.

**Color**: `primary` is the only accent: actions, links, focus and selection. Status tones are used only inside StatusBadge and alerts. Neutral hover everywhere (`bg-muted`).

**Radius**: `--radius-control: 8px`, `--radius-container: 12px`, `--radius-sheet: 16px`, `rounded-full` for pills and avatars.

**Elevation**: Level 0 is `content`. Level 1 is `card` + hairline border, no shadow. Level 2 is popover/menu with `shadow-md`. Level 3 is dialog/sheet with `shadow-xl` + `bg-black/40` scrim.

**Motion**: 150ms for state changes, 250ms ease-out for sheets and dialogs, no bounce. Wrap everything in `motion-safe:`.

**Controls**: heights 36 / 44 / 52, matching between button, input and select of the same size.

## 4. Remediation plan

Each phase is an OpenSpec change (repo rule: non-trivial work is spec-driven). Phases are ordered by risk-to-value. F0 unblocks everything else.

### F0 — Foundations: tokens and a11y quick wins (`ui-foundations-hig`)

- C1, C2, C3, m12: recalibrate `muted-foreground`, `input`, dark semantics and dark `border`. Extend `tokens.test.ts` to assert every foreground/background pair ≥ 4.5:1 (≥ 3:1 for borders) in both themes, so this cannot regress.
- M5: neutral hover; reduce to one accent.
- Typography ladder, radius tiers and control-height tokens in `tailwind.preset.js` + `globals.css`.
- C5: global reduced-motion rule.
- m6, m8: focus rings and the Spanish close label.
- Size: S–M. Mostly `packages/ui`. Visual diff on every screen; screenshot-check the main pages before merging.

### F1 — Component layer (`ui-components-hig`)

- M3: Button sizes re-based on control tokens (default 44).
- M4: IconButton hit-area expansion.
- C4, m11: `FormField` (label + description + error + aria wiring). Migrate forms progressively.
- M1, M2: `SectionHeading` on the ladder. Retire `common/Section` and the 28px variant.
- M9: EmptyState v2 and ErrorState with retry.
- M11: Card without resting shadow. Containers on `radius-container`.
- PageHeader: chevron size (m1), title uses `text-title-1`.
- Size: M. Tests per component (strict TDD per `openspec/config.yaml`).

### F2 — Admin consistency pass (`admin-ui-consistency`)

- M10: ConfirmDialog everywhere, plus `useBlocker` unsaved-changes dialog replacing `window.confirm`.
- M13: skeletons in EquipoDetail, KeyDetail and the snapshot/dialog panels. Add NotFoundState to both details.
- m2, m3, m4: breadcrumbs, page names, subtitles.
- m5: off-token cleanup. Add `lint_hardcodes` to `admin-checks.yml` / `installer-checks.yml`.
- Update `.claude/skills/admin-ui-patterns/SKILL.md` with the ladder and section convention.
- Size: M. Likely needs `chained-pr` if it goes over the 800-line budget.

### F3 — Installer as a native-feeling iOS app (`installer-mobile-hig`)

- M6: bottom tab bar (new `TabBar` in `@vitalock/ui`). Installer shell without sidebar/FAB.
- M7, m14: `viewport-fit=cover`, safe-area utilities, apple-touch-icon PNGs, meta tags, split icons.
- M8: sticky bottom action bar on TaskDetail. ConfirmDialog on "Finalizar".
- Secondary tasks (configure equipment, add comment) move to a bottom `Sheet` (`side="bottom"`, 16px top radius, grabber).
- M12: ConnectivityBanner in the shell; offline-disabled actions.
- M9 applied: Dashboard skeleton plus error handling on Dashboard and Tareas.
- m9, m10: 16px inputs, serial input attributes.
- m13: delete the dead dialog.
- Size: M–L. Validate on a real iPhone (standalone PWA) before merging.

### F4 — Delight and efficiency (backlog, independent)

- E1 ⌘K palette (admin) · E2 pull-to-refresh · E3 serial scanner · E4 translucent bars · E5 offline worklist cache · E6 large-title collapse.

### Quality gates to add along the way

- Contrast assertions in `tokens.test.ts` (F0).
- `lint_hardcodes` in CI (F2).
- axe check in the existing e2e (Playwright) on the main routes of each app (F1+).
