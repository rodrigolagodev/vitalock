## Deviations from Design

1. **`capitalize` CSS dropped on TechnicalItemsTable Tipo cell** (T-23): the inline table rendered `className="capitalize"` on the first cell, which word-capitalized multi-word labels ("Configuración de llave" → "Configuración De Llave"). DataTable's text first-cell renders `font-medium`; the drop is a correctness fix, and data-level behavior (label map lookup with raw fallback) is preserved exactly.
2. **UnitsTable is orphaned (W6 finding)**: `UnitsTable.tsx` has NO consumer anywhere in the app (only the `useUnits` hook is used by forms). It was still migrated per T-19/spec. **Candidate for dead-code removal — NOT removed**; the removal decision is deferred to archive/user. Parent wiring for it is N/A.
3. **OrderTareasTable always renders** (T-25): the page previously showed a conditional plain `<p>` for the empty case; the DataTable now renders the standard dashed empty state with the verbatim message "No hay tareas generadas para esta orden." — this is the spec's required "standard skeleton and dashed empty state" for the OrdenDetailPage inline tables.
4. **Tareas loading wired** (T-25): the page now destructures `isLoading` from `useOrderTareas` and passes it to OrderTareasTable so the skeleton shows during tareas fetch (spec consistency requirement).
5. **T-22 keys-composition test passed immediately**: keys orders already rendered only the mocked OrderItemsTable marker pre-refactor; the RED came from the technical-branch composition test (T-22b), which is the behavior the refactor actually changes.
